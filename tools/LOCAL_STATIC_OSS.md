# Local public image publisher (operator only)

Run from the release checkout, not from a web request. Reads regular blobs from one immutable Git revision, never media, working-tree symlinks, DB URLs, arbitrary attachments or caller paths. Private state is not an input. The untracked operator script may run against a reviewed, committed asset revision: `revision` identifies the source tree, not the script. The materialised `strict-oss-local.json` is a separate schema from `botend/services/site_image_assets.json`.

```
python -B -m tools.publish_local_static                     # offline discovery, no writes
python -B -m tools.publish_local_static --existing          # cold full verification, no PUT
# Dedicated 0700 operator-owned directory, outside web/static roots. Configure the
# normal Django settings on the OSS-capable host (never copy credentials).
PYTHON=.venv/bin/python bash tools/run_local_static_publish.sh /absolute/private/publication-state
```

The last command is the schedulable entry point; no service/timer is installed. Seed the directory with the trusted operator-produced snapshot to resume. Exclusive lock; previous verified entries reused only for matching current path, destination grammar and SHA-256. Removed or no-longer-approved paths are dropped. New/changed entries require full verification; writes use create-only content keys, not object overwrites. Failed attempts are diagnostics, never promoted. On cold recheck omit `--previous`. Do not promote a previous revision merely because a newer pass failed. Protect the previous receipt like a release artifact, not user input.

**Review a new asset:** site-owned UI artwork → add a reviewed exact path + byte hash in `PINS` and a discovery root if needed; inline combat CSS → review the passive SVG and pin its decoded payload hash. New files do not inherit redistribution rights from their directory. Game icon families are discovered by exact Git path grammar; dimensions and decoded MIME must match. Named OSS canonical bytes or the exact anonymous public WoW icon URL must match the Git bytes. `local_static_icon_proofs.json` keeps reviewed Git-path→SHA-256 proofs for originals where the publishing host cannot reach the upstream. These 38 proofs were verified byte-for-byte with the derived `https://wow.zamimg.com/images/wow/icons/{small|medium}/{name}.jpg` and `image/jpeg`. Never mint a proof by hashing a local file alone. A changed hash invalidates it. Do not import the historical `SyncPortalFavicons` cache wholesale: tool-link hash is *not* image provenance. For external editorial queues use the independent `tools.discover_editorial_images --urls` → `tools.publish_site_images` staging/publication path; this local job never feeds it arbitrary URLs.

**Consumption:** `images[identity] = [key, sha256]`. Static-file identity is the exact root-relative `/static/...` path; CSS payload identity is `css-sha256:` plus SHA-256 of URL-percent-decoded SVG bytes (not the CSS text). `receipts` stores `conditional-create`, `reused` or `previous`; only publish `images`. `held` counts excluded blobs; `errors` must be empty before promotion. Validate the entire map before use. Allow `site-images/v1/<same 64-lowerhex>.(jpg|webp|ico|svg|png|gif)` or the exact `wow_icons_oss/{small|medium}/<name>.jpg` corresponding to that identity (`wow_icons/small` → `small`, `portal/img/consumables` → `medium`). Construct the URL only as `https://oss.wowdaily.cn/` + validated key. No match → omit the slot or explicitly choose the already published first-party default, **never return the input**. Never strip a foreign URL down to a local basename. Do not pass this mixed local map to the external source-URL manifest reader.

For CSS replace the four declaration values in the correct theme (do not key by CSS property alone). For sprite `<use>`, preserve only the known symbol ID; don't blindly swap in a cross-origin `href`. Have the presentation owner test actual browser rendering or use a build-time/local inline symbol definition derived from the verified sprite. The existing `/favicon.ico` redirect is to Bloodmallet artwork (not first-party); no redistribution clearance was established for that or the remaining harvested favicons. Do not alias them as byte matches. Use the published `/static/portal/favicons/default.svg` as a deliberate fallback, including for the site favicon where desired.
