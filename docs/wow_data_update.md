# 装备与天赋当前资料更新

## 数据规则

装备和天赋都以游戏 ID 与来源分支关联。分支为正式服 `retail`、测试服 `ptr`、内测服 `beta`。构建号用于发现更新和记录来源，不再作为普通展示的匹配条件。不同来源发布速度不同，也不要求 Wago 与 Raidbots 构建号相等。

同一分支增量更新当前记录，保持数据库主键、装备选择和天赋版本稳定键不变。装备的装等、升级档位、制造品质等仍区分真实变体，避免把不同装等数值混用。旧批次引用读取时映射当前同 ID、同变体、同分支记录。

抓取缺失或失败的属性、特效、来源和天赋文本保留已有内容，并记录缺失字段，下轮即使构建号没变化也重试。成功更新只写差异字段。已有历史记录不批量删除；更新器不按新构建复制业务记录。已经冻结的模拟输入、任务结果和 DPS 数值保持原样。

## 调度和更新过程

迁移 `0232` 登记 `WowDataVersionMonitor`，接入项目现有后台调度器，默认每 12 小时检测，首次创建也等待一个周期。迁移 `0234` 将早期的 10 分钟／1 小时默认值调整为 12 小时，保留管理员设置的其他周期和开关；后台重启不再覆盖本任务的自定义周期。迁移 `0233` 增加装备变体分支字段并回填历史 PTR 标记。必须部署代码、运行迁移并启动现有后台任务进程后，定时更新才会实际执行。

后台启动一个独立工作线程，只领取装备天赋更新任务。普通监控线程排除该任务，更新期间仍可领取和执行其他到期任务。装备 Tooltip、天赋图标和文本、DB2 分段下载均限制最多 2 路并发；同一任务仍受数据库租约保护，多个后台进程不会同时重复更新。没有版本变化且没有待补字段时不执行大批下载；失败按下一检测周期重试，不密集重试。独立线程避免占用普通工作线程，但仍共享机器和数据库资源，不代表完全没有资源开销。

通用新建监控任务模板默认为 1 小时（3600 秒），覆盖后台表单、模型默认值和自动登记的兜底周期；迁移 `0235` 只修改模型默认值。装备天赋更新继续使用专用的 12 小时周期。

默认检测正式服以及已经启用天赋或装备资料的其他分支。更新持有现有任务租约，发布前再次校验执行权，防止过期进程覆盖新数据。

1. 分别检测 Wago 和 Raidbots 的来源版本；来源组合有变化或上次存在缺失字段时准备更新。
2. 获取当前目录，并补抓已有装备、强化和装等。Wago 提供天赋结构，缺失展示字段再从同分支 Wowhead 补充。
3. 天赋候选在隔离事务内导入和验证，然后回滚候选数据库记录；验收后的数据在发布事务中更新当前行。
4. 装备和天赋更新在同一发布事务提交。结构校验失败或数据库写入失败时回滚，继续使用现有资料。
5. 请求模拟结果展示快照重建，并让专精聚合任务重新计算。队列失败保留待办，下轮补偿，不反复发布同一批资料。

天赋和更新器的 Tooltip 文件使用每分支两个固定暂存槽交替更新，准备时不覆盖当前读取目录。执行记录仅保存状态、来源号、缺失字段和错误报告，不保存每个构建的装备及天赋副本。

## 读取入口覆盖

冒险手册掉落支持职业与拾取专精联动筛选，切换首领、难度和页签保留选择。拾取名单优先读取同分支 Wago `ItemSpecOverride`，普通装备结合 `ItemSpec`、`ChrSpecialization`、武器类型及主属性计算；神器圣物读取 `GemProperties`。缺少基础字段时按物品 ID 补抓 `Item`、`ItemSparse`，失败则保留现有名单并由后台重试，不在页面展示采集提示。手册全量采集和装备定时更新共用规则，更新覆盖中央装备以及活动手册中的全部掉落（包括没有中央装备记录的旧掉落）。PTR 手册覆盖层也参与分支检测。新增采集字段会使下一正常检测周期补采一次，不提高调度频率。

| 入口 | 更新方式 |
| --- | --- |
| 冒险手册掉落、装备详情和 Tooltip | 当前 ID、分支和装等读取；旧构建号不再隐藏属性或特效 |
| 配装器目录、装备、宝石、附魔和装饰 | 读取当前变体；同分支不同构建不拆成重复物品组 |
| 浏览器保存配装、分享链接 | 进入页面、切换职业专精、重新回到页面时恢复当前资料；保留选择和锁定部位 |
| 配装助手、已拥有装备 | 将旧引用映射当前同分支变体，保留外部装备 |
| 模拟结果列表与详情、结果展示快照 | 共用装备展示服务；发布后重建展示快照，冻结结果数值不变 |
| 天赋模拟器、玩家天赋树与天赋编码服务 | 稳定分支键读取；缓存键包含当前记录更新时间，旧版本链接解析到当前分支 |
| 专精统计聚合 | 按节点 ID 更新展示文本与图标，保留样本数和使用率 |
| 攻略中的装备、法术和天赋引用 | ID 解析；明确的来源分支隔离 |
| 手动装备目录导入与精确来源补采 | 激活更新复用当前批次与变体；身份、特效执行事实写入每分支当前值 |

显式离线导入且不激活的管理命令仍可准备待验收目录；它不属于定时更新的构建历史保存机制。旧数据兼容读取与冻结模拟结果的内部证据校验仍保留。Beta 展示资料独立；原有只支持正式服/PTR 的模拟执行能力未扩展为 Beta 模拟。

## 手动检查

单独补齐已有装备和手册的拾取专精（不改变其他字段，不重新发布整本手册；省略 `--apply` 只核对）：

```powershell
python manage.py sync_item_loot_specializations --branch ptr --build 12.1.5.70077 --apply
```

分支与来源构建必须对应，正式服使用 `--branch retail` 及正式服构建。命令输出已解析的物品 ID 和名单；重复执行相同数据不重复写入。

只读检测：

```powershell
python manage.py sync_wow_game_data --branch retail
```

执行更新：

```powershell
python manage.py sync_wow_game_data --branch retail --apply
```

`--branch` 支持 `retail`、`ptr`、`beta`、`all`。显式 `all` 会尝试三个分支；某分支上游不可用会记录失败并保留其现有数据。执行前需要已有赛季目录，更新器不会猜测赛季。

## 本地验证与边界

已在独立 SQLite 数据库迁移并验证冒险手册 1324 的五件问题装备均加载详情。配装器验证将浏览器中的旧力量数值 1 自动恢复为当前 199，耐力恢复为 4187，变体 ID 191 与锁定主手状态保持不变。

155 项定向回归与 3 项浏览器缓存逻辑测试通过，覆盖原位更新、旧构建读取、正式服/PTR/Beta 隔离、缺失字段保留、事务回滚、租约失效、队列补偿、缓存刷新以及手动导入。系统检查、迁移一致性检查通过。扩展模拟执行测试中的失败已与独立远端基线对照一致；部分其他测试在 Windows 上受项目既有 `fcntl` 导入限制。

正式服版本只读检测已连通 Wago 与 Raidbots，并成功读取来源构建号。最后一次实际页面复核使用本轮最新代码，页面脚本错误为零。

降低调度频率后的追加验证：调度、增量更新和 Tooltip 共 51 项测试中 49 项通过、2 项因 SQLite 不支持对应数据库并发场景而跳过；来源下载的 12 项回归通过。独立本地数据库执行迁移后，任务为启用状态、间隔为 43200 秒。验证了更新租约存在时普通队列仍可领取其他任务、独立线程不阻塞调用方、自定义周期在后台同步后保持不变。

本地验证未部署代码或修改生产数据库。没有执行完整上游装备及全职业天赋下载发布演练，因此上游完整同步仍需在实际后台运行环境验证；本地事务测试使用受控来源输入，不等同于线上全量同步验收。

拾取专精补齐已使用真实 PTR `12.1.5.70077` 来源验证：下载并校验 832 条普通规则、64902 条例外规则、60 条专精与 2409 条宝石属性，逐件核对副本 1324 的 12 件掉落基础数据，在独立本地库更新 12 件中央装备和 1 个首领的拾取名单。重复执行更新数为零。浏览器实测神圣、防护、惩戒分别显示治疗、坦克、输出饰品；智力单手剑和力量双手剑按专精正确分开。页面不显示数据采集提示，移动端无横向溢出。相关回归 112 项中 111 项通过，1 项仍受上述 Windows `fcntl` 导入限制；系统、迁移一致性和脚本语法检查通过。
