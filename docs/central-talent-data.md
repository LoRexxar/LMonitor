# 中央天赋与技能展示资料

## 数据边界

业务仅使用 `retail`（正式服）和 `ptr`（测试服）。同一套数据库、每分支一份当前资料；不按构建号新增天赋副本。构建号用于说明采集来源和保证一次采集内部完整，不能作为展示名称或中文描述的查询门槛。旧版本参数仍兼容识别所属分支。

本次没有新增业务表：

| 存储 | 用途 |
| --- | --- |
| `wow_talent_version` | 当前分支入口、来源目录与发布状态。正式服各页面共用相同默认入口，PTR 必须明确选择。 |
| `wow_talent_node_metadata` | 天赋结构与技能关联。新增 `is_current` 标志；移除的节点退出当前树，保留主键供旧引用使用。旧名称、原文和校订记录保留为采集输入及兼容资料。 |
| `wow_spell_snapshot.display_data` | 新增的最终展示字段；一个分支、一个技能在中文记录中保存一份中英文名称、图标、描述及光环描述。公共部分只存一次，专精和节点仅保存差异字段。 |
| `wow_spell_snapshot` 的原文字段、`wow_spell_effect_snapshot` | 技能更新监控、描述合成所需的原文与数值依据。原文不能被最终文字覆盖，合成也不能修改原文的更新时间。 |

节点编号和技能编号属于不同编号空间。英雄树标题不能用同号技能描述冒充；只有明确的展示技能关联或完整的技能描述引用可以参与合成。

名称补充的唯一约束改为分支入口、名称类型、引用编号，允许正式服与测试服的同号技能有不同中文。当前入口优先使用本分支校订；不跨分支借用中文。历史模拟输入、数值结果和已冻结记录不回写。

## 来源与中间文件

- 正式服主要来自 Wago `wow`；测试服主要来自 Wago `wowxptr`。历史技能来源别名在后台归并，不成为新增业务分支。
- 天赋结构、关联、原文来自 DB2；图标来自 DB2 图标关联与 Wago 文件映射。现有采集流程仅在缺字段时使用同分支 Wowhead 补充，PTR 对应 `ptr-2`。
- 资料位于 `.cache/wow_data_updates/{分支}/{a或b}/source/` 与 `talents/{内容摘要}/`。当前目录由 `wow_talent_version.source_dir` 指向。
- 内容摘要用于文件完整性和发布切换，不是业务版本条件。中央合成禁止偷偷读取未区分分支的全局 `latest` 目录。
- 展示文件属于可重建缓存。现有排行榜统计目录只接收正式服数据，并记录 `data_branch=retail`；测试服资料不能发布到同一路径。

## 写入与读取

统一采集发布成功后合成中央技能资料，再通知原有后台任务刷新展示文件。旧天赋维护命令也接入同一合成服务，候选导入、嵌套命令和只读预览不会重复发布。

技能效果补采按字段比较后更新；相同资料不删除重建。旧描述解析命令改为生成中央最终字段，不再把解析结果覆盖回节点原文。旧 DB2 迁移命令改用中央节点导入，不再创建独立的英雄树名称表。

天赋模拟器、玩家树、统计聚合、SimC 技能说明、APL 目录和攻略提示共用中央读取。请求期间不抓取外网、不回填数据库、不解析描述模板。兼容尚未回填的普通原文；含变量的未合成描述不会在页面临时猜算。因此发布时必须完成下面的数据合并步骤。

中文缺失仍如实记录为不完整，不能把英文或其他分支的描述标成中文。角色属性影响的实际伤害继续由模拟器计算，公共描述不保存某个角色的最终伤害。

## 发布及存量合并

以下命令由部署环境执行；本次开发没有连接生产库执行它们。

```powershell
python manage.py migrate
python manage.py sync_central_spell_display --branch all
python manage.py sync_central_spell_display --branch all --apply
python manage.py sync_central_spell_display --branch all
```

迁移 `0247` 增加最终展示字段和节点状态；`0248` 调整名称唯一约束。合并命令默认仅预览，支持 `--branch retail`、`--branch ptr` 和 `--batch-size 200`。正式写入后再次预览，预期 `created=0`、`updated=0`；`incomplete` 表示仍缺少中文或未完整解析的技能数量，不代表数据库迁移失败。

正式服资料发生变化时会通知已启用的专精聚合后台任务；由该任务原子发布中间文件。任务未启用时须按现有运维流程刷新统计缓存。上线前应完成中央合并，等待聚合刷新后再开放依赖新字段的页面。

本次不删除旧表和采集文件。旧原文不作为另一份独立的最终展示资料维护；后续清理旧输入字段需要单独确认其采集及历史报告用途。

## 本地验证范围

使用独立 SQLite 测试库验证结构迁移、预览零写入、重复合并零新增和零更新、别名归并幂等、跨分支隔离、跨构建号读取、公共文字去重、页面只读、移除节点退役及恢复时复用主键。

最终组合回归共 312 项：309 项通过，3 项已在修改前代码复现的 Windows 文件锁用例跳过。47 个 Python 文件通过语法检查，模型与迁移一致性检查、Django 系统检查及差异格式检查通过。

Windows 环境无法执行依赖 `fcntl` 的部分既有文件锁测试；已与修改前代码独立对比。生产数据库迁移、真实上游全量采集、Linux 原子文件发布以及线上页面验收未在本次本地开发中执行。
