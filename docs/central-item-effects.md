# 中央装备特效归并

## 数据职责

配装模拟器、冒险手册、模拟装备提示和增量模拟结果通过 `wow_item_display` 读取同一套资料。装备仍以 `WowItemSnapshot.item_id` 唯一标识，副本掉落关系不另建装备副本。

| 内容 | 存放位置 | 用途 |
| --- | --- | --- |
| 名称、图标与基础身份 | `WowItemSnapshot` | 各页面共用；正式服、测试服事实仍按原有分支规则隔离 |
| 公共特效 | `WowItemSnapshot.effects` | 分支内共用的中英文模板、技能标识和来源摘要 |
| 具体装备属性 | `WowItemVariantSnapshot.stats_json` | 保留真实装等、难度及品质对应的数值 |
| 特效参数 | `WowItemVariantSnapshot.effect_values` | 引用中央模板，保存当前变体数值及原文摘要 |
| 采集原文 | `WowItemVariantSnapshot.effects_json` | 暂时保留作来源证据、历史兼容和变更检测，不作为独立维护的翻译库 |
| 页面中间文件 | 现有装备、手册与模拟结果快照 | 后台生成的展示投影，可重建；不反向写回装备资料 |

这是兼容迁移，并未删除历史变体或采集原文。仍会存在原始证据和可重建展示文件，不能将本次改造理解为物理存储已完全去重。普通装备轨道和手册难度记录承载不同的属性证据，本次共用特效，不合并具有不同身份条件的变体。

## 中文和数值规则

- 有当前变体时，优先使用中央中文模板和此变体参数。只有同一来源的双语数值顺序一致且没有重复参数歧义，才允许位置参数复用；显式技能模板则校验变量身份。
- 不按品质或装等查找中文机制。缺少真实难度变体时，仍可展示同物品、同分支已收录的中文机制；数值替换为“数值待确认”，属性与适用性明确标为未确认。
- 已确认无特效的原生手册变体不继承其他变体的效果。
- 不同分支、不同技能、矛盾中文模板不会互相补值。英文里只有“秒”等中文单位不算已经汉化。
- 没有可靠中文对应时保留英文，不猜测翻译。预检的 `untranslated` 表示尚无中文的模板数量，不代表全站中文覆盖率。
- 同一来源未变时保留中央中文修订；后续只采到英文也不会擦掉已有中文。来源发生变化并提供新中文时，以新证据重新归并。

## 写入和文件生成

目录发布、手册导入、中文修复及规范化命令统一调用 `sync_central_effects`。手册批量导入先完成整批身份和并发校验，再统一归并，避免自己的公共字段更新被当成外部并发修改。

归并仅更新变化字段，重复执行不更新记录和时间戳。读取不触发回填或网络抓取；未回填的批量读取可使用本次已加载的变体在内存中生成兼容投影。

周期更新跳过手册专用 `difficulty_drop` 记录的普通轨道补采，避免把没有升级轨道的真实难度证据当作赛季升级装备重复抓取。

中央资料变化后通知装备目录与模拟结果快照刷新，手册使用共同的源指纹发现变化。继续使用现有后台构建、原子发布和旧文件回退流程。手册掉落范围仍逐项校验，允许“掉落范围完整、属性待确认、特效已收录”的部分展示。

图标继续取中央装备图标，通过 `wow_icon_oss_url` 使用既有 OSS 图标源；手册已有的图片资源代理兼容逻辑保留。本次没有增加新的图标抓取或复制目录。

## 上线步骤

以下步骤需要在正式发布时执行；本次本地开发没有修改生产数据库。

1. 合并时确认迁移编号没有与其他开发分支冲突，再按正常发布流程执行 `python manage.py migrate`。
2. 预检当前目录：`python manage.py sync_central_item_effects`。可重复使用 `--item-id 物品编号` 限定范围。
3. 应用回填：`python manage.py sync_central_item_effects --apply`。每批最多处理 200 个物品，可重复执行。
4. 再次预检，确认 `items` 和 `variants` 均为零；检查待补中文记录。
5. 按现有后台快照流程完成刷新，抽查配装、同物品不同难度手册、模拟结果中的中文与数值。

历史模拟输入及冻结执行资料不重写；本次调整当前展示和采集发布的公共资料。上线前仍需在生产使用的数据库及操作系统上验证迁移、锁和文件快照流程。
