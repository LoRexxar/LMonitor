# 全站站内统计

后台入口：系统管理 → 站内统计，地址为 `/dashboard/?section=site-analytics`。

## 发布与权限

1. 按项目原有发布流程应用迁移 `0230_site_analytics`：`python manage.py migrate`。
2. 按原有静态资源发布方式同步新脚本、样式，重启应用进程。应用启动时注册 HTML 注入中间件，无需修改主机配置文件。
3. 超级管理员自动拥有权限；其他账号需要在用户组中授予“站内统计”（`system.analytics`）权限。该权限同时允许查询统计和修改采集设置。
4. 若站点位于反向代理之后，在“采集管理与统计口径”中填写实际可信代理 IP 或网段。未配置时使用连接地址，不能直接信任任意客户端传入的转发头。多个代理从右向左校验信任链。

迁移后默认启用采集。没有迁移时原页面仍可显示，采集接口返回暂不可用。统计不会回填上线前的流量；本次开发验收使用独立 SQLite 数据库，没有修改生产数据。

## 采集范围

- 自动向 Django 返回的成功 HTML 文档注入一次脚本，覆盖前台、账号页、后台和通过页面路由返回的普通 HTML 报告。
- 支持整页加载、刷新、后台栏目切换、浏览器历史前进后退及页面缓存恢复。同一页面仅改变普通查询参数或锚点不增加 PV。
- 嵌入框架不重复计数；沙箱报告、下载、流式响应、非 HTML 接口和已识别爬虫不计入。直接由静态服务器或外部对象存储返回的文件不经过 Django，不能由本中间件注入。
- 浏览器禁用脚本或拦截请求时无法计数；本功能反映浏览器访问，不等同于服务器访问日志。停用本地存储时退回当前页面内存标识，跨页面 UV 可能增加。
- 来源只发送域名对应的源地址，服务端仅存域名；路径去掉查询参数和锚点，仅保留经过校验的后台栏目。IP、访客和会话仅保存带服务端密钥的摘要，不保存原始 IP、账户、标题或完整来源 URL。

## 指标与聚合

| 指标 | 口径 |
| --- | --- |
| 浏览量 PV | 成功写入的页面访问事件数；相同上报编号只记录一次 |
| 访客 UV | 所选范围内浏览器访客标识去重；更换浏览器或清除存储会改变标识 |
| 独立 IP | 所选范围内有效连接 IP 摘要去重；同一网络多人共用 IP 时小于访客数 |
| 会话数 | 访客与会话组合去重；30 分钟没有新页面访问后重建会话，同源标签共享标识 |
| 人均浏览页数 | PV / UV |
| 每次会话页数 | PV / 会话数 |
| 多次浏览访客 | 所选范围内浏览至少 2 次的访客数，不等同于跨周期回访用户 |
| 最近 15 分钟访客 | 当前筛选结果中，最近 15 分钟内发生页面访问的访客去重 |

日期范围为 1 至 93 天，按站点时区计算。汇总独立数跨日去重，不能将每天的 UV、IP 或会话数直接相加作为汇总。日期、区域和路径前缀筛选同时作用于全部聚合结果。

提供每日趋势、小时分布、热门页面前 50 项、来源前 20 项、设备、浏览器、操作系统、区域、登录状态，以及访客/IP 浏览次数的 1 次、2–5 次、6–10 次、11 次以上分布。来源缺失显示“直接访问 / 来源未知”，不将其断言为直接访问。

## 管理与运行边界

- 可暂停/恢复采集，配置排除路径前缀和可信代理；设置写入要求后台权限和 CSRF 校验。
- 采集端校验同源来源、格式与长度，对单 IP 每分钟上报最多 120 次。限流依赖 Django 缓存；若使用进程内缓存，该上限按工作进程分别计算，不能代替入口流量防护。
- 统计明细保留在本项目数据库中，本版本不自动清理。汇总通过索引和数据库聚合执行，随着明细增长，应结合实际查询耗时安排后续归档策略。
- 当前站点使用的固定时差范围通过 UTC 平移聚合，不依赖 MySQL 时区表。若更换为具有夏令时的时区且查询跨越时差变化，需要数据库具备对应时区规则；缺失时明确报错，不显示错误的日期趋势。
- 密钥改变会改变摘要结果，因此同一访客或 IP 在密钥改变前后可能被视为不同对象。
