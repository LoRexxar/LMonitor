# 职业热修报告旧值恢复

## 问题与修复

报告 149 的区间为 EU、enUS、push 112881 → 113268。原页面把大量效果展示为“旧值未核实”。本次沿用原始 Wago 来源，修复三个数据路径：

1. 补历史报告原来只使用区间内部的前态。现在优先复用区间内前态，为缺少前态的技能表记录继续查询区间之前的历史；道具、地图等非技能表不额外扩展历史查询。
2. 同一个推送可能同时发布多个客户端版本。采集、历史匹配、全量报告投影和重建校验的物理身份加入 build，避免把合法的版本变体判为重复或互相覆盖。
3. 部分旧记录的内嵌 ID 是空字符串。仅这种明确省略 ID 的格式使用来源 record_id；非空错误 ID、缺失字段、未知结构、冲突历史仍然拒绝。

前态使用对应版本的结构解码，保存完整前态来源，并在职业效果中标注前次推送与版本。临时查询失败不再永久缓存为空历史。

没有可解码历史前态时，职业效果可补充同版本客户端基表对照。该对照独立保存为 client_baseline，不设置 before_verified，也不伪装成前次热修。默认每次最多查询 24 次，硬上限 32 次；沿用 WAGO_HOTFIX_FIELD_BASELINE_LOOKUPS 设置。浮点序列化的末位差异不算变化，整型掩码保持精确比较。

## 已有报告的更新入口

更新代码不会自动改写已发布报告。原 `rerender_wow_hotfix_report` 默认仍只重绘已冻结事实；增加 `--refresh-predecessors` 后，才为已解码但缺少前态的 Spell 表来源重新查询历史，并同步保存事实与两份 HTML。

执行时继续提供独立核对过的来源数量、来源 ID 集合 SHA-256，以及原 source_facts_json 的 SHA-256：

```text
python manage.py rerender_wow_hotfix_report --report-id 149 --expected-count <已核对来源数量> --expected-id-sha256 <已核对来源ID摘要> --expected-facts-sha256 <原事实正文摘要> --refresh-predecessors
```

该选项不能与 `--full-only` 合用。原始来源、新值、区间和采集游标保持不变；补齐旧值后允许剔除实际未变化的职业条目，并更新职业计数。地区扫描锁、事实摘要、已有基表对照保留检查、暂存文件校验及失败回滚继续生效；保存前通过数据库行锁复核事实未被并发修改。任一原始新值解码发生漂移即停止替换。
