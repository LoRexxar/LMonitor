# 技能归一化全局增伤复盘

本次修复针对全职业的全局增伤归类与前置排除，不修改线上数据，不部署。结果来自本地真实 SimC 导出，不是线上页面验收。

## 原因

- Python 保留了天神下凡、巨人打击、激怒三个示例法术的兜底清单。
- 原生 DBC 规则主要接受无技能标记、覆盖所有伤害学校的光环，漏掉了职业技能标记、直接/周期修正、零基础值和引用精通数值的效果。
- 仅凭一个天赋的整段说明，可能把其中的全局增伤错套给该天赋附带的单技能 buff。例如凝血同时描述目标易伤与血之疫病强化，两者必须分别归类。
- 上方表和下方剔除没有完整候选目录可以交叉核对；共享职业 buff 的不适用状态也可能出现在其他专精中。

## 修复

`0044` 补丁以通用作用域判定替代示例 ID：读取 buff 本身的增伤效果、官方 DBC 效果说明、数值引用和原生公共乘区。零基础值不会直接被当作无增伤；精通引用会校验专精。技能、学校、自动攻击、宠物专属、暴击和减伤等局部声明不能截取为全技能增伤。只有缺少 buff 自身说明时才使用有界的 DBC 描述引用闭包，避免混合天赋说明串台。

同一份作用域事实同时用于生成前的状态排除、场景枚举前的剔除、上方全局表和导出协议检查。判定按玩家和状态缓存，不在每个技能、目标数、层数中重新分类。纯被动全局增伤仍在职业初始化前去掉；混合天赋保留其他机制，归一化时清零其全局 buff。

上方表只展示当前配置可用的状态，并汇集逐天赋配置中发现的状态。不同专精共享的 buff 对象不等于该专精启用了对应天赋。直伤和周期各写一次的相同百分比只记录一次，动态或无法确定的倍率保留未确定状态，不伪造固定值。

新增完整候选审计目录；全局声明与候选分类不一致、重复声明、未知依据或全局状态进入伤害场景均报错。删除 Python 的三个示例 ID 兜底。原生协议升级到 17、数据集升级到 27，旧导出器不能作为新版本生成器使用。

共识别 53 种可用全局效果。在成功导出的配置中：候选与声明不一致 0、全局表缺失或多出条目 0、原生场景和最终伤害列表残留全局状态 0。逐专精清单及二进制摘要见同目录 JSON 文件。

逐项复查了未归入全局的增伤说明，保留单技能、学校、周期专属和仅触发后续效果的状态。包括凝血的血之疫病强化、不同条件分支中的技能名、审判的下一个圣能技能易伤等反例，均纳入回归。

- 175 项相关测试中 171 项通过；4 项受 Windows 不提供 `fcntl` 的既有平台限制影响。最新定向回归 24 项通过，包含从最终补丁提取并实际编译执行的 C++ 分类、动态数值、引用循环和前置剪枝测试。
- 44 个补丁在独立的上游检出中顺序应用成功，最终源码与原生编译输入一致；旧补丁按生产 LF 文本应用，Windows 文件同步适配留在隔离构建中。
- 上方表与下方列表的交叉复核可使用 `scripts/audit_simc_global_damage_scope.py` 重跑。
