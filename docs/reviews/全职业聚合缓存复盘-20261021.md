# 全职业数据聚合缓存复盘

日期：2026-10-21。范围：当前工作区的调度、排名、人物、战斗事实、装备天赋、统计计算及文件发布。本报告记录本地实施与验证，不代表生产部署完成。后续已按用户要求提交修复并合并远端夜间串行调度、发布校验更新。

## 结论

原链路有缓存，但缓存覆盖不等于整个任务可增量执行。活动缓存不能代替人物详情缓存；部分团本补采仅有进程内缓存；部分计算只在输出时判断重复；范围内某一页失败会重取此前成功页；装备资料存在缺口时会重新进入完整准备过程。这些成本可以叠加，不能把数小时运行全部解释为数据量大。

用户已核对的人物资料 3 小时 54 分、装备/天赋单分支 36–76 分钟是生产运行总时长。本次没有取得同次运行的完整分段请求记录，无法确定各项占比，也不能把本地计算回放的降幅直接套到这两个总时长。

## 链路覆盖与处理

| 环节 | 原有能力或缺口 | 本次处理与新鲜度边界 |
| --- | --- | --- |
| 排名发现与差异写入 | 已按业务键比较新增、变化、退出；排名本身会变化 | 保留原刷新周期，不能因为旧排名存在就停止发现新玩家 |
| WCL 排名分页 | 完成整个副本/首领后才有检查点；失败范围内成功页重复获取 | 成功页持久化，绑定采集周期；重启继续；新周期重新请求；坏页不认证为可复用 |
| Raider.IO 人物详情 | 活动缓存没有覆盖详情获取；不同入口与专精重复请求 | 按赛季和角色身份共享响应；最长 24 小时，已观察到的排名内容变化提前失效；失败退避、租约防重 |
| 跨专精人物信号 | 不同专精装备/分数本来就可能不同 | 分专精保存比较基线，避免同一角色在不同专精间来回失效；详情响应仍共享 |
| 活动与队伍 | 已有独立缓存及更新周期 | 人物详情命中仍经过活动自身更新判断，不用详情时钟冻结活动 |
| Battle.net 属性 | 成功后可能永不刷新；旧待采人物不断累积 | 日常核对当前前 20 名；成功缓存 24 小时，失败 5 分钟至 6 小时退避；保留手动补齐入口；批量读缓存 |
| 战斗事实与团本缺失天赋 | 大秘境已有中央事实、分组请求、负缓存及预算；团本兜底使用内存缓存 | 团本接入同一中央事实与负缓存，跨难度、重启复用；预算等待不认证成不存在 |
| 团本普通统计 | 每轮重新计算全部首领/难度，输出阶段才去重 | 按首领、难度、专精缓存计算结果；输入、人物资料、中央展示依赖变化才重算 |
| 大秘境统计 | 已有完整专精指纹；部分变化或发布失败仍重复计算单本 | 保留整体复用，补单本与汇总结果缓存；发布失败不丢掉已完成计算 |
| 团本爆发统计 | 已有原始事件缓存、逐页恢复、范围指纹 | 保留现有机制，验证限流、权限失败、并行成功及后续重试 |
| 装备目录与提示 | 完整同源版本可跳过；缺字段会重新准备 | 同构建提示复用 24 小时；完整来源阶段可独立恢复；缺属性/必要特效不固定为完成；构建变化立即重新获取 |
| 天赋来源、提示与解析 | DB2 有下载检查点，图标有缓存；解析阶段重试重复导入 | 保留成功提示，补缺失或过期条目；按来源文件内容和补充资料复用解析结果；仅修改文件时间不触发重导入 |
| 发布与调度 | 发布去重较晚；中央资料更新未必重开已发布周期 | 校验索引与全部明细后提前复用；中央正式服资料更新后重开统计检查；完成后不反复重开 |
| 等待与观测 | 缓存命中仍固定等待；难以区分来源与计算耗时 | 限速等待移至人物/属性实际请求路径；补缓存计数、专精耗时、来源/导入/发布阶段日志 |

计算缓存使用内容指纹，不只比较更新时间。无时间戳变化的批量数据修正、缺失资料补齐、版本切换都会重新核对。缓存是可重建的中间结果，原始排名与战斗事实仍使用中央数据源。

依赖检查同时移除了空装备范围的目录查询，以及当前版本解析器对同一正式服版本的重复查询。公开统计原有的原子入口、旧版本保留、发布所有权约束继续保留。本地 Windows 验证使用真实跨进程文件锁，没有替换成空锁。

## 实测收益

使用已采集的 40 专精团本样本，每专精 3 条，共 120 条，配合 6,657 条已保存天赋元数据，在隔离 SQLite 内存库中运行真实统计函数。禁止外部联网，固定已采集资料，不临时补充上游内容。首次、无变化及单条 DPS 修改使用同一批输入。

| 场景 | 耗时 | 数据库语句 | 真正统计计算次数 |
| --- | ---: | ---: | ---: |
| 原有全量计算 | 11.850 秒 | 720 | 40 |
| 首次建立缓存 | 15.285 秒 | 1,374 | 40 |
| 输入不变重跑 | 3.329 秒 | 574 | 0 |
| 单专精一条 DPS 变化 | 3.596 秒 | 594 | 1 |

无变化重跑耗时减少约 71.9%，数据库语句减少约 20.3%；单点变化耗时减少约 69.7%。首次建立缓存慢约 29.0%，这是完整依赖核对与持久化的代价。原有输出、首次缓存输出、缓存命中输出的全部 40 个业务内容摘要一致；单点修改只改变 1 个范围。

这是实际样本的计算阶段回放，不是线上完整任务压测。样本只有每专精 3 条，且没有完整生产装备目录，不能据此承诺人物任务或装备分支的最终分钟数。

另有隔离请求计数及故障验证：20 个已有详情且信号不变的角色在同一天重跑，人物详情请求从 20 次降至 0；过期后恢复请求。成功 WCL 页跨重启复用，新周期重新获取；跨难度缺失天赋只读取一次战斗事实；单个副本变化保留其他副本计算；团本、大秘境发布故障均能复用已完成计算后重试。

证据：`tmp/full-chain-replay.py`、`tmp/full-chain-replay-results.json`、`tmp/full-chain-replay-final.log`、`botend/tests/test_full_chain_incremental.py`、`botend/tests/test_raiderio_profile_cache.py`。

- 任务执行器验证隔离了生产插件注册表，保留真实基础插件与执行器逻辑；完整注册表会导入未修改的 Linux 专用文件锁模块，未宣称其在 Windows 可运行。合并验证同时修复了 Windows 路径分隔符导致的发布检查点复用失效，既有恢复与失效测试通过。
- 最终统一回归 166 项全部通过，覆盖人物缓存、身份校验、跨专精复用、过期刷新、失败退避、装备分支、天赋阶段、WCL 周期、并行采集和发布恢复。日志为 `tmp/full-chain-core-final.log`。
- 本地 HTTP 测试真实经过请求、分页、限流、并行排空与数据库落库；仅允许回环地址，禁止外部请求。Windows 文件锁测试以第二个进程验证互斥及释放。
- 迁移一致性、Django 系统检查与差异格式检查通过。新增迁移为 0251 与 0252，生产库尚未应用。
- 扩大测试时发现原有大秘境依赖测试仍按旧的天赋解析/展示口径构造样本；取原 HEAD 的聚合实现重跑代表用例，同样失败，未将其记为通过。另有旧公开视图断言与当前汇总口径不一致。

## 后续生产验收口径

部署并应用迁移后，应分别记录首次预热、输入基本不变、局部变化和失败恢复四类运行。核对人物真实请求数/命中数/退避数，来源准备、天赋解析、统计和发布各段耗时，以及新周期、新构建、24 小时过期数据是否如期更新。冷启动开销与稳定运行收益分开比较；只有取得这些生产记录后，才能确认 3 小时 54 分及 36–76 分钟实际降到多少。

缓存不会替代必要的数据发现，也无法消除上游接口耗时和限流。身份无法可靠解析的旧人物回退路径仍不认证为可共享缓存；不以误用他人数据换取命中率。
