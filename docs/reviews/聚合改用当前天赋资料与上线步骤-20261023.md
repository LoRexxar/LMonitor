# 聚合改用当前天赋资料与上线步骤

## 最终契约

本方案替代《中央天赋引用生命周期修复-20261023.md》中的旧身份保留方案。聚合保存选择、数量、比例等事实；名称、图标和说明读取当前中央资料。天赋身份或结构变化使相关聚合失效，后台使用已有采集事实重新计算，不为统计保留退役节点，不要求重新采集 WCL。

同一节点的身份修改原位更新；被中央来源移除的结构节点物理删除。没有变化的节点不写入。删除只针对实际移除的主键，按最多500个主键拆分语句；正常中央发布仍处于原有事务中，保持资料更新原子性。未新增历史表、引用计数表或逐次页面访问写入。

新文件引用为树类型、节点号、天赋号、技能号，不再保存必须长期存活的数据库节点主键。旧引用格式仍能按其中的业务标识找到当前节点；这只是读取旧文件格式，不会保留或读取旧身份行。身份不匹配时不把旧使用次数挂到新技能上：中间缓存未命中，详情页面返回503并提示“天赋资料已更新，统计正在重新生成，请稍后重试”。请求不现场聚合、不写数据库。

## 重建范围与时序

中央发布后沿用现有 WCL 周期重放机制，读取已完成周期的采集事实。副本、首领计算仍使用内容指纹和私有文件缓存。无变化范围复用，不重复发布。

资料依赖不再包含所有版本的构建号、标签、路径等全局变化；结构CSV只计入该职业相关条目，赠送节点只计入该职业当前构建有效的规则。解码器需要同职业各专精的完整节点序列，因此共享职业树变化会影响该职业的多个专精；不是承诺每次只重建一个专精。无关职业的原产物可以继续复用。

最终发布在当前资料版本锁内重新核对结构指纹。计算期间身份变化会拒绝本轮发布、保留原入口并进入既有失败重试。中央资料在聚合开始后更新，即使发生在聚合完成前，也会触发下一轮重放，避免被完成时间吞掉。手工仅重建部分专精或仅大秘境，不会把其他范围标记为已经消费中央更新。

直接SQL或独立修复脚本不一定更新中央发布状态，执行这类维护后须主动运行聚合命令；页面读取只报告失效，不代替后台调度。

新文件携带结构指纹，能够识别节点增删、身份、树结构、有效赠送规则及相关CSV变化。旧格式在首次升级重建前没有完整指纹，因此上线必须完成下面的全范围预热与检查。

原始日志中明确提供、且不同于节点编号的技能号如果与当前节点冲突，只排除该日志的天赋统计，保留性能等其他样本。旧采集器把节点编号复制进技能号的记录继续按节点编号解析，不误判为冲突。仅有节点编号的旧事实按当前资料解释；系统不会凭空恢复不存在的旧技能证据。

## 已上线0254和历史节点的处理

保留0254文件及其执行记录，不回退、不伪造迁移状态。新增0255_use_current_talent_metadata向前升级：

1. 先检查恢复原唯一约束是否会与当前记录冲突。发生冲突时，在删除之前失败并列出范围，不猜测应该保留哪条当前记录。
2. 只删除 `localization_only=False, is_current=False` 的退役结构节点。每批500行，迁移不包裹一个覆盖全部历史节点的大事务；中断后重新执行会继续处理剩余行。
3. 保留当前节点主键、当前内容、独立名称补充记录及其余资料版本。恢复原来的节点唯一约束和版本级联删除语义，运行时移除身份分离与软删除覆盖。

0255包含实际数据删除，不能依靠逆迁移恢复旧身份。升级前保留现有数据库备份和聚合入口备份。若必须恢复旧代码，需要匹配的数据库与文件备份；不要在清理后直接运行0254时代的写入器。

清理历史行会产生一次性的数据库删除及binlog；每批限制规模，不承诺完全没有binlog。MySQL表空间可能保留空闲页，删行不等于磁盘文件立即缩小；本补丁不执行表重建或OPTIMIZE。持续增长的控制点是以后不再创建身份历史行，而不是频繁全表清理。

## 线上更新顺序

以下命令在生产项目目录、原生产虚拟环境中执行，默认操作当前活跃赛季；如指定赛季，可给聚合和检查命令添加 `--season` 参数。

### 一、停止旧进程并更新代码

保持聚合任务37暂停，停止旧代码的中央资料更新、聚合以及会修复天赋的进程。安排维护窗口：迁移会删除旧引用依赖的历史行，预热完成前不要混跑旧Web或旧写入进程。备份数据库及当前聚合入口，沿用现有部署方式拉取本次交付代码。

```text
git pull --ff-only origin master
python manage.py showmigrations botend
python manage.py check_talent_aggregation --database-only
python manage.py migrate --plan
```

第一次检查中的“退役结构节点”是本次预计清理量，可以大于0。“当前唯一约束冲突”必须为空；非空时命令失败，先处理列出的当前数据冲突，不能忽略错误强行继续。

### 二、向前迁移

```text
python manage.py migrate
python manage.py showmigrations botend
python manage.py check
python manage.py check_talent_aggregation --database-only --require-current
```

确认0254、0255都显示已执行；退役结构节点为0、约束冲突为空。未曾上线0254的环境也执行同样的正常向前迁移，不使用fake，不删除历史迁移文件。

### 三、使用已有采集事实重建

中央更新器继续暂停，使用新代码手工预热。手工聚合可在任务37关闭时取得原有统一任务租约，不需要先打开自动调度。

可以先验证一个专精：

```text
python manage.py aggregate_spec_stats --class Mage --spec Fire
python manage.py check_talent_aggregation --class Mage --spec Fire --require-current
```

然后完成全部当前赛季范围：

```text
python manage.py aggregate_spec_stats
python manage.py check_talent_aggregation --require-current
```

如果命令明确提示赛季尚无任何WCL采集周期，使用已有原始表兼容预热：

```text
python manage.py aggregate_spec_stats --allow-legacy
python manage.py check_talent_aggregation --require-current
```

如果提示已有采集/发布周期未完成，不绕过周期保护，也不手工改周期状态。使用新代码恢复现有调度器及任务37，按原阶段续跑：已完成采集的周期只继续聚合；尚未完成采集的周期仍需先完成其未完成部分。待周期完成后再执行检查。不要同时运行手工聚合和调度聚合。

检查命令逐一核验当前赛季配置要求的两种团本难度、各副本及大秘境汇总，校验详情文件哈希并通过正式读取接口读回；旧版、缺失、损坏和身份失效都会返回非零退出码。

### 四、恢复服务并验收后续更新

检查全部通过后，以新代码启动Web和后台进程，恢复中央资料任务及任务37。复核团本、大秘境页面的样本数、天赋选择和统计提示。

下一次正常中央资料发布后，运行：

```text
python manage.py check_talent_aggregation --require-current
```

身份刚变化而后台尚未完成时，检查会报告待重建。正常调度完成后应恢复全通过。监控任务失败、退役节点数量和binlog增量；本补丁不声称已经完成生产MySQL容量或并发锁等待实测。

### 五、回收旧文件和中间缓存

0255清理的是数据库退役节点，不会立即删除旧聚合文件。被重新计算的中间缓存在固定路径替换；其他中间缓存按原TTL回收。旧公开版本仍受当前版本、回退版本和48小时宽限保护，不因节点已删除而额外永久保留；回收器只核验文件完整性，不展开中央资料引用。

先盘点和预演：

```text
python manage.py audit_aggregation_storage
python manage.py maintain_aggregation_storage --kind published --scope-limit 40
python manage.py maintain_aggregation_storage --kind work
```

验收后执行有界回收：

```text
python manage.py maintain_aggregation_storage --kind published --apply --scope-limit 40 --passes 4
python manage.py maintain_aggregation_storage --kind work --apply --passes 4
```

如果范围被旧故障禁用，按输出中的具体赛季/职业/专精，使用 `--repair-disabled-scope` 完整校验后再回收；不要手工删除禁用标记。单个旧中间文件超过默认64MiB、详情超过既有读取上限、来源不明文件等仍按原规则拒绝处理，这次不扩大删除范围。MySQL binlog也不属于这些命令的清理对象。

旧文件保留并不保证能够跨天赋身份变更回退展示；回退文件与当前身份不相符时应重建。这个边界是取消旧身份兼容后的明确取舍。
