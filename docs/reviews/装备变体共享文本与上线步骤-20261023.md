# 装备变体共享文本与上线步骤

## 原因与修改

原实现虽然已有中央特效翻译模板和数值引用，但每个变体的 `effects_json` 仍保留完整原文，目录又展开出特效和 Tooltip。同一件装备的不同装等因此反复保存同一段文字。此前的接口字段裁剪解决了无关资料随刷新返回的问题，没有解决这层重复存储。

现在同一物品的相同描述结构存入 `WowItemSnapshot.variant_text_templates`，变体只保存模板引用和数值参数。结构不同的真实特效分别建模板，字符串中的千分位、小数格式、来源字段和原始类型完整保留，不通过猜测公式重算数值。业务代码通过 `effects_data` 读取还原后的原文；属性、装等、附魔、宝石和制造属性保持原契约。

短文本或独有描述在计入模板开销后可能更大，因此按模板组核算收益；无收益的组保留内联数据。不会为统一格式扩大存储。

新资料采集复用已有模板，中央特效同步后整理共享文本。相同内容重复采集和维护不执行数据库更新；格式转换不修改业务更新时间，也不改变冻结证据校验值或大秘境聚合依赖指纹。不会仅因整理存储而触发全部专精重新聚合。

本次减少的是可重复的变体描述，不删除来源证据、属性事实、用户配装或历史分享。没有宣称清空整张表或减少所有数据库字段的相同比例。

## 自动转换和回收

- 迁移 `0256` 只增加共享模板容器和回退保护，不在迁移过程中全表改写描述。
- 监控进程已有维护线程默认启用变体整理。每轮处理最多 200 个物品，每个物品独立事务；维护间隔沿用 `SNAPSHOT_CACHE_GC_INTERVAL_SECONDS`，默认一小时。需要监控进程正常运行，单独启动 Web 不会启动该线程。
- 扫描游标保存在 `var/variant-text/cursor.json`，与其他进程通过文件锁互斥，重启可续跑。多实例应共享此私有目录，也可通过 `VARIANT_TEXT_MAINTENANCE_ROOT` 指定既有共享存储。
- 单个物品转换失败会回滚该物品、记录主键和错误，继续后续物品，下一轮完整扫描再重试。错误不会被当成成功。
- 模板只保留数据库现存变体实际使用的内容，扫描包括历史批次，避免误删仍在使用的模板。变体被既有保留任务清理后，无引用模板在下一轮整理时自动去掉。这里不额外保留退役模板历史。
- 目录文件自带它使用的模板，读取和历史文件回收不依赖数据库模板的生命周期。目录仍沿用已有文件保留和回收规则。

无需在每次中央资料更新后手动运行转换或清理命令。首次历史转换会产生一次必要写入，后续无变化时不写数据库。MySQL 表空间已分配文件不一定立即缩小；释放的页可复用，本次不自动执行表重建。

## 目录格式选择

新浏览器支持共享文本目录，并在原有筛选、Tooltip 和换装逻辑之前还原；已打开的旧页面仍可读取展开格式，服务端从同一文件生成响应，不保存第二份展开正文。

目录生成同时比较 JSON 与 gzip 的体积，只有两者都更小时才采用共享文本格式。真实公开的战士狂怒头部样本含 9 件装备、164 个变体：强制模板化使 JSON 从 346,783 字节降至 259,571 字节，但 gzip 并未受益，因此自动选择保留原 gzip 表达。不能将 JSON 缩小比例直接称为磁盘或网络节省比例。

## 验证结果

- 核心后端 245 项测试通过，前端 30 项测试通过。覆盖存量转换、重复同步零写入、模板回收、错误回滚、冻结证据、聚合依赖、历史分享、属性与强化、目录双格式和只读请求。
- 仓库资料 `ptr_kithix_unbound_12_1_5.json` 的 10 件装备、180 个变体，逐条验证原始内容、序列化结果、冻结证据校验值一致。描述 JSON 连同模板从 152,776 字节降至 47,123 字节，减少 69.2%。这是样本字段体积，不是生产数据库全量统计，也不是 MySQL 物理页测量。
- 真实公开样本在隔离 Edge 浏览器中完成加载、已有配装刷新、换装和属性面板一致性验证。固定刷新延迟 2.5 秒的对照中，槽位显示为 3.404 秒与 0.485 秒，目录显示为 3.414 秒与 0.729 秒；这是包含前一轮首屏修复的本地对照，不能解释为本次模板化独自产生的提速，也不是部署后的生产耗时。
- 扩展回归曾运行 240 项，其中 237 项通过，3 项因 Windows 无 `O_NOFOLLOW` 或缺少符号链接权限失败。对应装备文件保护与冒险手册文件发布路径仍需 Linux 环境验收，没有通过屏蔽安全检查将它们算为通过。
- 单独验证了数据库迁移回退保护、完整原文恢复和恢复后的模板清空。

证据日志保存在本地 `tmp/variant-text-final-20261023.log`、`tmp/variant-text-js-all-20261023.log`、`tmp/variant-text-fourth-20261023.log`、`tmp/variant-text-browser-20261023.log` 和 `tmp/variant-text-migration-20261023.log`，不纳入版本库。本次没有连接生产数据库或执行生产迁移。

## 线上更新

先按现有部署方式停止旧版监控、采集和 Web 进程，避免旧代码与新格式写入混跑。在线上应用目录、既有虚拟环境与配置中执行：

```sh
git pull --ff-only origin master
python manage.py migrate --noinput
python manage.py check
python manage.py collectstatic --noinput
```

随后启动新版 Web、监控和采集进程。模板与静态脚本需要一起部署。新脚本版本为 `20261023_text_templates`、`20261023_variant_text`。

检查监控日志的 `kind=variant_text` 和“装备共享文本维护”：应看到检查物品数、修改变体数、下一次起点及错误数。默认 `VARIANT_TEXT_MAINTENANCE_ENABLED=True`、`SNAPSHOT_CACHE_GC_WORKER_ENABLED=True`；如部署已有显式关闭项，需要恢复相应任务。新目录会按后台版本检查重建，已发布的目录在此期间继续可读。

打开已有配装，检查槽位和候选装备、不同装等的描述数值、换装后的属性、宝石附魔、制造绿字、锁定状态和旧分享恢复。等待自动维护推进后，再查看相同物品是否仍显示一致。存量较多时首次转换跨多个维护周期完成。

需要审计或加速首次整理时，可选用下列命令；日常更新不需要执行：

```sh
# 只读预检首批
python manage.py compact_variant_text --limit 200
# 应用首批
python manage.py compact_variant_text --apply --limit 200
```

后续批次通过 `--after` 指定输出的“下次起点”，直到本批物品数小于请求上限。命令按物品提交，重复执行已完成的批次不会改写相同数据；若途中失败，应先检查对应错误，再从上一个已知起点重试。

## 需要回退旧代码时

旧代码不理解共享引用，不能直接回退代码或删除模板字段。先停止维护、采集和 Web 进程，用本版本还原所有批次：

```sh
python manage.py compact_variant_text --restore-inline --apply --limit 1000
```

同样按“下次起点”用 `--after` 继续，直到本批物品数少于 1000，再执行：

```sh
python manage.py migrate botend 0255
```

迁移会拒绝删除仍被变体引用的模板字段。还原完成后按现有部署方式回退代码，保持维护窗口，在旧版代码下重建已登记目录并重新收集静态资源：

```sh
python manage.py refresh_gear_catalog_snapshots --force --limit 10000
python manage.py collectstatic --noinput
```

确认全部已登记目录重建并回读成功，再恢复服务，避免旧前端接收新格式目录。回退路径不需要重新采集 WCL 日志。
