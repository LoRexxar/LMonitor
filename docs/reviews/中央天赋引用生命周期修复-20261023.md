# 中央天赋引用生命周期修复

> 后续调整：旧身份保留方案已由《聚合改用当前天赋资料与上线步骤-20261023.md》替代。以新文档中的0255向前迁移、当前资料引用和重建步骤为准。

## 问题与责任边界

上一轮聚合优化确认了压缩转换和即时读回，却没有覆盖中央资料随后更新这一必要生命周期。读取端拒绝错身份是正确的，但中央写入端仍会按职业、专精、树和节点号匹配旧行，再原地覆盖talent_id、spell_id。这会让合法旧产物在中央更新后无法解析，属于存储引用设计的缺口。

用户提供的线上证据为80份最大团本、大秘境详情在私有目录转换后80/80完整一致，紧凑正文146.13MiB降至56.96MiB；这些是用户的现场验证，不是本轮本地独立测量。用户明确公开入口未切换，聚合任务37暂停。本轮没有连接生产、恢复任务或操作公开入口。

## 修复契约

- 保持现有文件格式、节点主键及身份校验。旧格式无需重采WCL日志。
- 同一版本、职业、专精、树、node_id、talent_id、spell_id的身份保持稳定；身份变化时，在事务内退役旧节点，创建新身份行或复用已退役的相同完整身份。
- 旧行留在原来的中央元数据表中，原主键和旧身份不变。普通查询只看当前行，历史引用通过all_objects按版本、专精和完整身份读取。
- 统一覆盖save、QuerySet.update、bulk_update和批量补回。结构节点的delete改为退役，禁止直接修改主键、用表达式覆盖身份或通过原始查询集删除结构节点。删除仍有节点的资料版本会被PROTECT阻止。
- 只改名称、图标、描述时保留原行；批量身份比对只读取身份字段，同身份文字更新保持批量SQL。聚合读取仍是批量只读，不写库。
- 部分身份修复没有提供新文字时，不把旧技能说明搬给新技能；返回旧身份时复用该身份原有文字。中央发布显式提供新身份的展示字段，包括空值。
- 资料引用选择同时核对输入已有的节点、天赋与技能标识，不因同名或同描述误绑另一身份。信息相同且均可匹配时优先当前行。
- 相同身份反复发布不产生每日全量资料副本；只有变化的身份增加行。本轮不自动物理清理退役节点，不能在尚未证明所有文件引用消失时删除它们。

这些保护覆盖本项目运行时ORM入口，不是数据库触发器。旧代码进程或直接SQL仍可能绕过应用规则，升级时必须停用旧写入进程。已经被旧代码覆盖、且没有保留下原资料的引用，补丁不能凭空恢复；需要从保留的完整产物或备份重新转换。

## 数据库迁移

新增0254_preserve_talent_node_identity，扩展节点唯一约束以允许同节点、同技能但talent_id不同的历史身份共存，调整基础管理器及版本删除保护。迁移不重写现有节点主键、不复制全表正文。数据库仍需要执行约束变更，MySQL上的实际DDL时长未在本机测量。

新旧身份共存后旧唯一约束不再适用，因此该迁移明确禁止自动逆迁移。出现上线异常时不要回退数据库到0253或让旧更新器重新写入；统计产物入口的正常历史回退仍然支持。

## 验证

联合回归覆盖154项：节点替换、只改talent_id、返回旧身份、退役和版本级联保护、失败回滚、发布读取与中央更新交错、同身份批量更新、错误引用继续拒绝，以及现有本地化、技能显示、中央更新、快照和私有缓存契约。真实中央发布方法完成更新后，已有团本、大秘境详情和工作缓存继续通过正式读取接口返回完整原结果；第二轮同身份中央发布仍复用新主键。

旧迁移测试原先直接使用运行时模型，新增删除保护后改用0253的历史模型，历史迁移行为本身没有修改。首次新测试夹具中的节点编号、模拟来源挂载和团本难度预期已修正，失败日志保留。

40专精120条已保存真实团本样本在隔离内存数据库回放，40/40完整对象一致，未压缩正文仍为4,706,128字节。该结果不代表线上80份或每日全量。日志为tmp/talent-identity-40spec-20261023.log，结果为tmp/talent-identity-40spec-20261023-results.json。

最终联合日志：tmp/talent-identity-delivery-20261023.log。测试环境为Windows和隔离SQLite；没有宣称完成生产MySQL并发锁竞争、线上全量迁移或实际空间释放验收。

## 上线顺序

1. 维持聚合任务37暂停，停止所有仍运行旧代码且会写中央天赋资料的进程，包括独立更新任务和手动修复脚本。保留现有公开入口。
2. 更新修复代码，先检查迁移计划，再执行迁移：

```text
python manage.py migrate --plan
python manage.py migrate
python manage.py showmigrations botend
python manage.py check
```

确认0254_preserve_talent_node_identity前有[X]，然后以新代码重启相关进程。任务37继续暂停，不要因为进程重启而自动恢复。

3. 使用已有私有转换流程重新核验80份详情。再进行一轮受控中央资料更新，读回更新之前已经转换的这些文件，并核验当前和回退入口；检查完整业务事实及全部引用，没有空结果或身份解析失败。允许同身份的中央文字修正更新展示，不能改变历史选择、数量和结构事实。
4. 验证通过后，按专精转换、完整核验并原子切换；失败范围继续保留原入口。格式迁移不要求重新采集WCL日志。
5. 全部待切换范围验收后再恢复聚合任务37。历史文件按原48小时及回退保护规则回收；私有缓存按既有TTL回收。不要删除中央退役节点来抢先释放空间。

本轮交付提供引用生命周期修复；生产切换、任务恢复以及现场80份更新后的持续可读性仍由线上验收确认。
