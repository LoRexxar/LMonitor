# 日志分析系统复核

2026 年 11 月 25 日，本地开发环境。范围包含 Portal 日志分析的 31 个路由项、Dashboard 的两项账号管理、13 张业务表，以及私有目录中的归档、事件索引和公开数据缓存。路由数量包括上传分片、下载、进度查询、授权回调及旧入口跳转。

本轮本地回归共 134 项通过，涵盖日志分析、12.1 实录回放、上传与断点续传、后台权限和存储维护故障隔离。Django 系统检查通过，模型与迁移一致。真实 WCL 查询与使用测试替身的部分在下表分别注明。

## 页面与请求

| 用户动作 | 页面与请求边界 | 核对结果 |
| --- | --- | --- |
| 打开日志分析 | 顶部导航进入 Portal。上传日志与关联角色是两个获取入口，日志库负责选择来源和报告 | 对 31 个路由逐个发起未登录请求，30 个跳到登录页，OAuth 回调跳回受登录保护的授权页 |
| 上传、暂停、续传 | 浏览器 Worker 本地扫描。提交场次清单后，按场次读取一次已收分片清单，仅发送缺少的分片，最后提交解析 | 修复了上传页只停止浏览器传输、服务端仍预留完整容量的问题。主动暂停现在等待当前请求结束，对本批剩余场次逐一确认暂停。已提交解析的场次继续处理 |
| 关联公开角色 | 站内已绑定角色可直接关联。手动关联校验区服与名称，将关注来源保存到当前账号。公开查询使用应用渠道 | 修复手动关联后重复查询第一页的问题。账号与来源共同限定缓存，可复用 45 秒，缓存缺失时正常查询。缓存命中时，关联及首次展示合计一次 WCL 列表请求 |
| 读取自己的 WCL 报告 | 私有渠道使用站内账号对应的 OAuth 授权。撤销绑定后访问私有单场索引会再次检查绑定 | 本地没有真实私有授权。通过测试替身验证授权交换、刷新、解绑及旧索引访问控制 |
| 从日志库进入战斗目录 | 勾选报告后先看战斗分组。WCL 目录按渠道批量读取元数据，每个渠道最多 20 份，同场多视角结合时间及参战阵容识别 | 用已关联的「炎色雷灬」实查，本页列出 20 份公开报告。首份报告的目录包含 1 个分组、39 场战斗。操作前后上传日志均为 4 份 |
| 分析单场及大秘境 | 选择单场后读取该战斗。大秘境可选全程或具体波次，按所选范围查看伤害、事件和证据 | 修正本地钥匙内首领误显示团本开荒入口的问题。同组有多场时提供「副本首领对比」 |
| 首领开荒与场次比较 | 目录与开荒图读取场次摘要。WCL 双场对比明确选定两次尝试后才读取伤害、治疗和死亡明细 | 请求区分输入不合法、缺少授权、报告不可见和上游故障。尚能展示本地报告的混合列表可保留内容并显示渠道错误 |
| 回放、角色及事件证据 | 回放按时间窗读取施法、光环、血量、走位等。波次与全场各自计算累计伤害，以对应的已过时间计算 DPS | 新建 WCL 单场索引预计算伤害分桶，旧索引继续从事件计算。用同一批事件核对了两条路径的分桶、总量和首领范围 |
| 角色对比与公开标杆 | 上传样本支持指定同场、跨场及共同范围内选优。大秘境标杆取已采集的同层同专精最高分，团本取同难度同专精最高 DPS。详细技能数据按需读取 | 本地有 200 行大秘境排行，团本排行表为空。团本标杆匹配逻辑有固定数据测试，当前开发库不能用真实排行完成该项验收 |
| 团队分析册、机制与 AI | 成员身份限定可读报告。书签保存查询条件，AI 结果按报告发布版本或多场证据指纹区分 | 回归覆盖成员撤权、旧书签重开、证据定位、结果复用及数据变化后失效 |
| 后台账号管理 | Dashboard 中分别管理上传回收、公开角色上限。每个网站账号一行，打开编辑窗口保存覆盖值，使用详情按账号读取 | 两个管理项均要求超级管理员。按页读取账号、策略和关联对象。普通账号可以使用 Portal；后台授权独立。删除账号时清理两种账号覆盖策略 |
| 等待及失败 | 浏览器长导航先显示等待页，再执行分析请求。进度查询读取当前用户的短期状态。事件 JSON 和回放分块直接响应 | 修正独立角色对比入口的路由名，使其也能显示等待提示。慢请求、取消等待和失败重试均有浏览器回归 |

## 主库字段及存储边界

在本地库逐表比对了 Django 模型和实际列名。13 张表全部一致，外键检查无异常，迁移已应用至 `0293_combat_account_upload_key`，两种账号策略均无孤立记录。

| 业务表 | 保留理由及字段判断 |
| --- | --- |
| `CombatLogReport` | 管理一份上传的所有者、原始大小、分片大小、有效期、解析状态和已发布索引。上传键负责续传，解析批次隔离失效任务，已发布版本保证重建期间可以继续读旧版。数据库唯一约束已改为账号加上传键。预留字节用于暂停和续传，待替换关系保证新日志成功发布后才回收旧日志 |
| `CombatLogPart` | 每个分片一行，保存报告、序号和摘要。报告加序号唯一，支持校验、断点续传和按序还原。分片内容存于文件目录 |
| `CombatLogPolicy`、`CombatPublicRolePolicy` | 分别管理上传份数、保留天数、是否满额替换，以及公开角色名额。全站默认与账号覆盖使用同一张策略表的不同记录。删除账号时两者都已补上清理。直接通过数据库删除账号时，字符串策略键缺少外键级联保证 |
| `WclUserBinding`、`CombatPublicSource` | 前者保存站内账号的 WCL 授权身份、加密凭据、令牌期限及刷新协调信息。后者保存关注的公开角色或公会、地区、服务器、专精和展示资料。两者生命周期和授权方式不同 |
| `CombatLogCollection`、`CombatLogBookmark` | 分析册承载成员与报告的多对多关系。书签保留已选范围、筛选项和锚点，打开时重新校验访问范围 |
| `CombatLogMechanic`、`CombatLogReview`、`CombatLogMechanicReview` | 机制规则保存触发技能、响应条件和时间窗。报告复盘结果绑定版本与事件锚点，跨场机制结果绑定实际样本指纹。规则可独立编辑，多份结果可并存 |
| `CombatLogPurge`、`CombatLogScheduler` | 回收记录在报告元数据删除后仍须存在，以便重试文件删除。调度表的一行用于协调解析准入。到期回收沿用 LMonitor 维护周期 |

4 份已发布归档的 SQLite 索引均通过 `PRAGMA quick_check`，每份有 14 张数据表。最大样本原文为 9,866,255 字节，其主库摘要按紧凑 UTF-8 JSON 计为 1,686 字节。原文分片和事件索引位于私有文件目录。WCL 单场索引在独立目录缓存 24 小时。公开标杆事件摘要同样缓存 24 小时，此次补上了过期文件的物理回收。

## 请求成本与待验证项

- **日志库查询已实测改善。** 同一账号、同一页、4 份上传日志，数据库查询从 12 次降至 8 次。新增测试分别放入 1 份与 5 份报告和分析册，验证查询次数不随行数增长。
- **日志搜索仍有规模限制。** 当前可以按文件名或活动摘要 JSON 模糊匹配。开发库的查询计划使用有效期索引，并为去重和排序建立临时结构。跨报告搜索扩大时，应按真实数据量测量，再决定是否建立独立的活动名称索引。
- **原文件、上传量和磁盘占用分别计量。** 本地原文件上限默认 2 GiB。Edge 测试用 12.1 实录重复拼成恰好 2 GiB 的输入，手动选择一场 Voidscar Arena，实际上传 9,794,058 字节，分 19 片。落盘的 gzip 原文共 931,985 字节，SQLite 分析索引为 9,113,600 字节。测试也验证了超过上限 1 字节时会在本地拒绝扫描。全部场次模式会累加保留的每场数据，单场样本只能说明该次上传的体量。
- **分割位置经过网络验证。** 从选择文件到勾选场次，浏览器观察到的写请求为零。点击上传后，服务端实收的 19 个分片与所选场次字节数完全一致。续传先在浏览器重新识别对应场次，再核对分片清单。旧版整文件记录引导重新按场次上传。
- **跨来源聚合仍有边界。** 上传、WCL 公开和私有报告可以在同一个战斗目录中选择，当前分别按来源成组。一次战斗跨渠道重复出现时，系统尚未统一其身份。WCL 报告内角色编号也有报告作用域。将这些数据用于联合排名之前，需要可靠的战斗与跨服角色匹配。
- **WCL 缓存有独立的磁盘成本。** 打开公开单场不会占用账号上传份数，但事件索引会占用服务器私有磁盘。现有回收按时间执行，缺少全站 WCL 缓存总字节上限。多人在同一天打开大量不同场次时，峰值磁盘占用仍需容量验证。
- **开荒推进与走位受源数据约束。** WCL 目录的推进图连接各次尝试的百分比摘要。战斗内的实时血量走势、楼层和站位需要对应事件样点。本地上传目录当前未提供团本阶段和结束血量摘要。私有 WCL 实号、真实团本最高排行、多进程缓存命中率和生产数据库查询耗时均留待对应环境验证。
