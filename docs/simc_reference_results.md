# 前台数据模拟管理

## 范围与入口

- 前台仍为登录内测页 `/portal/simc-reference/`，没有增加公开导航入口。
- 前台保留“专精模拟资料／模拟排行榜”导航；后台取消顶部三项导航，公开配置管理、模拟结果管理及模拟排行榜统一从既有侧边栏进入，排名数字之外也可直接进入榜单。前后台根入口 `/portal/simc-reference/rankings/` 与 `/dashboard/frontend-simulations/rankings/` 仍分别遵循登录与后台权限要求；后台原有两个独立侧栏管理页保持不变，不增加前台全站导航入口。
- 后台“内容运营”下设“前台数据模拟管理”父目录，包含公开配置管理、模拟结果管理和模拟排行榜三个入口；“公开配置管理”位于 `/dashboard/frontend-simulations/publication/`，“模拟结果管理”位于 `/dashboard/frontend-simulations/results/`，不放在现有 SimC 菜单下。权限为 `frontend.simulations`；超级管理员自动拥有，其他后台用户由现有用户组分配权限，无需通用 SimC 历史任务权限。
- 两项功能均处于后台公共框架内，复用后台顶栏、侧边栏、页脚与明暗主题。公开配置页只负责目录同步和公开清单保存；模拟结果管理在页面顶部通过下拉菜单选择专精，下方同页显示所选专精的组合、状态、DPS、报告与重跑操作。公开配置与结果管理使用独立视图类与模板，拒绝跨页面提交操作。
- `/dashboard/frontend-simulations/results/` 自动选择首个可用专精。顶部使用原生 `select`，按职业以 `optgroup` 分组，当前专精标为选中；没有独立专精目录页或“返回专精列表”步骤。选择变化后跳转原有路径 `/dashboard/frontend-simulations/results/<spec_key>/`（路由名 `simc_reference_spec_results`），更新下方组合；多分支时在所选专精内切换正式服／PTR。
- 原入口 `/dashboard/frontend-simulations/` 仅处理 GET 重定向，默认进入公开配置页，旧 `tab=results` 请求转入模拟结果页。新页面不依赖 `tab` 参数，已移除同页双标签导航。
- 旧结果链接 `/dashboard/frontend-simulations/results/?config=ID` 重定向至对应专精路径并保留查询参数；原旧入口仍先转入独立结果入口。
- 公开范围按专精维护装备、天赋、APL 三类显式白名单，同时要求启用该专精的前台展示。清单适用于该专精的所有分支；资源本身仍须满足共享、启用及适用专精等条件。新增共享资料不会自动公开。
- 不读取个人任务或 Benchmark 面板历史结果。模拟范围是同一专精、同一正式服／PTR 分支的每份白名单装备 × 每份白名单天赋，只使用天赋明确绑定且也在白名单中的默认 APL。
- 默认单体和 5 目标，各 300 秒、10000 次迭代。固定时长站桩，显式关闭团队增益、职业团队增益与额外选项；装备及消耗品仍来自所选共享配置。

## 管理流程

1. 从侧栏进入“公开配置管理”，点击“同步可用资料目录”，建立可管理的专精与分支设置。目录同步不发布资源；前台读取不会建任务。
2. 优先选择唯一共享专精模板，其次选唯一共享通用模板。正式服默认使用 `production` 后端，PTR 使用 `ptr`；缺失或有歧义时保留未配置状态，由管理员选择。
3. 在公开配置页选择专精，分别勾选装备、天赋与 APL，并启用前台展示后保存。撤回专精或某份资源后，相关内容和结果立即从前台隐藏，并阻止依赖它的尚未派发任务。
4. 从侧栏进入“模拟结果管理”，通过顶部下拉菜单选择专精，下方展示该专精的组合和状态；需要时切换正式服／PTR。展开“模拟条件”，保存后端、模板、目标数、时长和迭代次数。目标数为 1–20 的不同整数，最多 10 个场景；时长 10–1800 秒；迭代次数 100–100000。校验失败时保留输入并自动展开条件表单，便于修正。
5. 点击“补齐已公开方案结果”。请求仅登记组合，已有 SimC Worker 每次维护周期最多派发 5 个任务。使用已有后台队列，优先级 20，可交给本地或 Agent 后端执行。已成功且输入一致、或正在排队运行的组合会被跳过，失败组合可再次补齐。
6. 当前专精与分支的“配置组合”以表格展示，每行是一组装备、天赋、默认 APL，三项资源分别占列；单体和 5 目标默认各占一列，列中同时显示状态与有效 DPS，列头注明各 300 秒。管理员自定义目标数后按实际场景动态生成列。所有当前公开装备与天赋的组合都展示，即使没有模拟记录；未模拟行显示“未模拟”和 DPS 占位符“—”，占位符带有“暂无 DPS”的可访问名称。
7. 尚未模拟且配置完整的组合可在行尾点击“开始模拟”，仅登记该行各场景；重复提交会去重。有记录的可运行组合提供“重跑组合”，当前输入仍在处理时按钮禁用并显示“模拟处理中”。“重跑已公开方案”用于当前专精所选分支的批量重跑。相同输入重跑时保留上次当前有效 DPS，并显示最新重跑状态；最新失败时即使旧 DPS 仍有效，状态也使用失败样式。
8. 行尾将主要操作、历史记录数与报告链接分层显示；默认报告链接为“单体报告”“5 目标报告”，整行没有可用报告时，当前公开组合显示“报告待生成”，历史只读组合显示“暂无报告”。点击记录数进入当前专精内的组合历史；尚未派发的记录支持取消，取消后仍留在当前专精的方案历史。撤回公开或默认 APL 变更后的旧组合标为“历史组合”，仅供查阅并保留历史入口。报告使用本模块独立子路由 `/dashboard/frontend-simulations/results/<id>/report/`，仅允许读取该结果绑定任务、且 Run 同属该任务的已完成 HTML 报告，不再导向通用任务详情。
9. 缺失或未公开默认 APL 的装备与天赋组合仍保留，显示“默认 APL 待配置”和完善配置提示，不能启动。是否可运行还须通过当前快照校验；维护设置停用时返回可理解的配置错误，不将该情况作为不存在的页面处理。
10. 后台组合表与榜单中的装备、天赋和 APL 名称为提示按钮，悬停、聚焦或点按时按需加载，保持在原表格内；按 Esc 或点击外部关闭。提示打开时可用上下方向键、PageUp／PageDown、Home／End 滚动长内容，按钮提供快捷键说明。装备仍为槽位、物品名、装等及属性覆盖摘要；天赋直接复用现有 SimC 后台的 `TalentTreeThumbnail.render` 绘制缩略树，不再列出截断的天赋名称摘要；APL 仍最多显示 6 组、每组前 3 项优先级与条件摘要。完整展示请打开对应的前台配置，提示不依赖入口所在位置；后台不提供完整详情页。
11. 前台与后台均在每个场景的 DPS 下提供“全职业”和“本专精”排名链接，默认单体与 5 目标共四个入口，点击跳转独立排行榜页面。数字表示“名次／有效组合数”，分母不是职业数量，也不限同一装备。排行榜可切换全职业／当前专精及单体／5 目标，未模拟场景不可点击；页面展示当前装备、天赋、APL 摘要及完整榜单，当前行使用底色与“当前配置”标签标出，并支持锚点定位和焦点定位。前台返回链接保留专精及三类资源选择，后台返回对应专精与分支配置。未模拟或没有有效结果的组合不显示虚假排名。
12. 前台榜单中的装备、天赋和 APL 名称链接携带完整 `spec/profile/talent/apl` 参数，打开对应组合并切换到该资料标签；每行另有“查看配置”。后台榜单名称继续使用提示和天赋缩略图，每行“前台配置”在新标签页打开对应完整组合。前台顶部导航用于资料与榜单往返，后台则统一通过侧边栏切换管理页和榜单。

## 资料提示访问与版本

- 提示接口为 `/dashboard/frontend-simulations/results/<spec>/preview/<kind>/<id>/`，`kind` 为 `profile`、`talent` 或 `apl`，返回 `name`、`description`，天赋另带标准 `talent_render_model` 供现有缩略图组件绘制；不额外查询天赋模拟器接口。接口沿用 `frontend.simulations` 权限，请求携带完整组合的 `config`、`profile`、`talent`、`apl` 参数，目标编号必须与对应组合字段一致。旧 `/resources/` 详情路由已撤销，访问返回 404，不重定向至完整后台详情。
- 仅当前公开组合或当前专精、分支下确实存在模拟记录的历史组合可访问。目标资源必须仍为全局共享且属于同一专精；装备还须属于相同正式服／PTR 分支。目标资源转为私人、跨专精、装备分支不符、目标编号不匹配或组合不存在时返回 404。缺失默认 APL 不妨碍符合上述条件的装备和天赋摘要阅读，不可用资料不生成提示入口。
- 提示展示资源的当前版本，并明确说明历史模拟输入以对应报告为准；历史组合可读不代表已重新公开。接口仅接受读取，响应禁止共享缓存及搜索引擎索引；后台提供天赋缩略图，不提供完整配置代码、独立天赋详情页或 APL 原文。

## 数据与一致性

- `SimcReferencePublication` 保存按专精启用的三类公开白名单；`SimcReferenceSimulationConfig` 保存专精与分支的设置；`SimcReferenceSimulation` 保存每次专用模拟的快照、任务关联、状态和有效 DPS。
- 所有结果管理 POST 必须提交至专精路径，并校验配置、方案和记录属于当前专精与所选分支。结果根路径的 POST 返回 400，跨专精访问配置或操作记录返回 404，避免无明确专精范围的操作或串用其他专精的记录。
- `simc_reference_management.public_combination_keys` 根据当前专精、分支的公开装备与公开天赋生成组合，使用天赋绑定且已公开的默认 APL；APL 不可用时仍保留待配置行。`scheme_results` 先按稳定顺序展示当前公开组合，再追加历史组合，不依赖已经存在的模拟记录。表格展示的资源正文与场景数据在分页后加载；排名另行批量读取跨页、跨专精的可比结果及资源，验证当前签名，不能把表格分页当作排名范围。GET 读取不会创建任务或模拟记录。
- `start_scheme` 校验配置属于路径指定专精，并再次核对装备、天赋、APL 三元组属于当前公开组合，仅提交该行且使用 `force=False` 去重；原有重跑使用 `force=True`，仍跳过正在处理的相同输入。行内可操作状态由当前快照校验决定，历史组和配置不完整组不能启动。
- 输入签名包含装备、天赋、默认 APL、模板的编号与内容哈希，分支、后端编号与构建版本，以及场景参数。通过统一任务服务创建任务，冻结四种资源版本。
- 排队期间资源变化会失败并提示重新生成；任务创建期间变化会回滚，避免把新内容当成原输入。
- 专用任务在 `request_manifest.reference_backend` 中携带后端约束。公共任务解析器在执行前再次检查本地后端声明版本，并写入 Run 清单；Agent 领取这类任务还须具有匹配的实测 `binary_revision`。版本不匹配的 Agent 跳过该任务，继续领取其他适合的工作，不改变普通任务原有的独立更新规则。后端声明版本已经变化时旧任务失败，避免永久等待。
- 准备阶段中断且 15 分钟未更新的记录可重新领取；认领时间防止过期执行者覆盖新状态。任务与登记记录在同一事务内关联。
- 仅已完成任务中唯一的已完成 Run、有限且大于零的 DPS、未标为无效的结果，以及相符的执行记录后端版本，才会转为成功。只读取必要的 JSON 标量，不加载完整分析报告。
- 前台只查询当前公开组合的成功结果。输入、后端版本或默认 APL 变化，资源停用或转私有，白名单撤回、专精停止公开，或维护设置关闭时，旧结果不展示。相同输入重跑期间仍展示上次成功结果，直到新的成功结果可用。
- 前台装备代码移除内嵌天赋与 APL，避免借装备公开泄露未公开的内容；未公开天赋也不从装备内嵌代码回退展示。
- 历史记录保留，后台显示“配置已变化，前台不展示”。前台结果区展示场景条件、DPS 及全职业／本专精公开组合排名，不暴露日志、用户信息或历史面板数据。
- 英雄天赋筛选通过实际天赋方案影响结果；APL 子板块的英雄树筛选只控制阅读视图，不改写模拟输入。

## 公开组合排名

- `botend/services/simc_reference_rankings.py` 的 `_current_cohorts` 为摘要排名与完整榜单提供共同的比较组，前台 `public_results` 与后台 `scheme_results` 使用同一规则。比较组要求正式服／PTR 分支、后端版本与 `game_build`、时长、迭代次数、模板正文及全部 `simulation_params` 相同；模板编号或专精标签不同但正文相同的配置可以比较。场景目标数属于比较参数，因此单体与 5 目标不会混排。
- 仅纳入当前公开、维护启用、已完成且 DPS 为有限正数的有效组合，严格校验结果签名与当前资源快照一致；每个配置签名只取最新成功记录。排队重跑期间保留上次有效结果及其排名，资源或条件变更后失效的历史结果不参与。
- 全职业排名覆盖全部可比专精的有效公开组合，本专精排名只取其中当前专精的组合；均覆盖所有分页，不限定相同装备。DPS 相同采用 `1、1、3` 并列名次，分母为对应范围内有效组合总数。排名读取不写库；本地已有 4 次批量查询断言，生产规模查询耗时尚未测量。
- 前台独立排行榜 `/portal/simc-reference/rankings/<config_id>/<signature>/<scope>/` 返回完整 HTML 页面，仅登录用户可读；后台独立排行榜 `/dashboard/frontend-simulations/rankings/<config_id>/<signature>/<scope>/` 使用 `SimcReferenceRankingsView`，要求 `frontend.simulations` 权限并保留后台侧栏与主题。`scope` 为 `overall` 或 `spec`。作为当前配置定位依据的结果若已不公开或过期，返回 404；响应禁止缓存及索引，名称通过 Django 自动转义，不返回报告、日志或用户信息。
- 两个榜单根入口分别名为 `portal_simc_reference_rankings_entry` 与 `simc_reference_rankings_entry`，只读选择当前有效公开结果，可优先使用查询参数 `config`，随后跳转既有精确榜单 URL；没有有效结果时返回完整空态页面。根入口不创建模拟或发布资料，精确路径的当前签名校验保持不变。
- `ranking_page_context` 生成范围、场景切换与返回链接，`leaderboard` 提供当前配置及可用场景签名。榜单全量输出，不受后台组合表每页 20 行限制。前台返回参数包含 `spec/profile/talent/apl`，后台返回专精路径并保留 `config`。所有排名入口均为普通链接，共享脚本仅增强当前行定位与聚焦；已移除异步请求、取消请求、重试和收起逻辑。

## 视觉维护入口与边界

- 延续现有 Portal 与后台功能页体系，既有主题与视觉约定见 [专精模拟资料界面改版](simc_reference_redesign.md)。本轮仅扩展前台结果区与后台公共框架内的管理模块，不新增全站品牌或设计系统。
- `static/shared/css/simc-reference-layout.css` 是模拟模块统一布局的来源，由前台资料、前台排行榜及后台管理基底共同加载，版本为 `20261110_unified`。五页统一使用 `simc-page-heading`：最大内容宽度 1256 像素，桌面／手机外留白 32／16 像素，面板内边距 24／16 像素，章节间距 24／20 像素，面板圆角 12 像素、控件圆角 8 像素，一级标题 26／22 像素。后台宽度还受既有侧栏和内容区约束，前后台保留各自主题颜色。
- 排行榜返回链接与标题同排，窄屏换行，榜单正文使用统一主题底板。后台不再渲染顶部模块导航，三项侧边栏入口分别高亮当前页面。前台页面根节点及后台模块滚动容器设置 `scrollbar-gutter: stable`，避免长短页面切换时因滚动条出现而改变宽度；手机后台内容留白为上下 24、左右 16 像素，保留原侧栏。表格说明与正文内边距对齐，后台子模板不重复加载榜单样式。
