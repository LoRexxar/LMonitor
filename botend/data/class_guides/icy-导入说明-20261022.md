## 线上导入

将 ZIP 上传至服务器，在项目根目录使用线上已有的 Python 环境运行。命令中的包路径按实际上传位置调整；沿用服务器当前的 Django 配置，不使用本地 SQLite 测试配置。

先进行完整包校验，不写入数据库：

```console
python manage.py import_class_guide_drafts --input-zip botend/data/class_guides/icy-initial-digests-20261022.zip --dry-run
```

预期输出：`校验通过：40 篇草稿，0 条术语`。

执行导入：

```console
python manage.py import_class_guide_drafts --input-zip botend/data/class_guides/icy-initial-digests-20261022.zip
```

首次导入且没有同名 Icy 文章时，预期输出：`导入 40 篇，跳过 0 篇；保留目标环境 0 项术语冲突`。

必须显式传入 `--input-zip`；省略该参数会使用系统原有的 Maxroll 初始化包。

本包直接兼容仓库现有的 `import_class_guide_drafts` 命令，导入本包不需要修改数据库模型或部署新增生成脚本。线上须已具备当前版本的攻略导入命令和专精模型，包括噬灭专精编号 `1480`。

## 导入行为

- 每篇文章绑定独立专精编号，文章标识统一以 `icy-` 开头。
- 标签为 `icy`、`12.1.5`、`通用`、`导读`，与 Maxroll 文章并存。
- 首次导入默认在前台显示；可在职业攻略管理页调整可见性或归档。
- 保留原文作者元数据，前台作者卡片显示“站内编辑／中文导读整理”，正文另列原文作者。
- 使用当前 Markdown 格式，包含“专精导读”“原文章节”“来源信息”三个章节。
- `source_markdown` 保存导读的初始化基线；它不是 Icy Veins 原文全文。来源元数据中的 `content_kind` 同样标识内容范围。
- 同一个包重复导入会跳过未变更文章；已有人工正文会保留。原有的人工标签和可见性也沿用现有导入器的保护行为。
- 包内术语列表为空，不写入或覆盖线上术语库。
- 只提供手动初始化包，没有新增定时同步任务。

## 后续重新生成

生成脚本可以通过 `--collect 新目录文件路径` 重新采集目录元数据。网站版本或正文变化后，应重新核对中文摘要，再使用以下参数生成新的包：

```console
python scripts/build_icy_guide_bundle.py --source-index botend/data/class_guides/icy-source-index-20261022.json --summaries botend/data/class_guides/icy-summaries-20261022.json --output 新导读包.zip
```

生成脚本拒绝覆盖已有采集文件或 ZIP。若需要完整攻略正文，请提供有权使用的正文文件，再按当前 Markdown 组件格式转换。
