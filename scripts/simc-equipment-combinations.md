# 基准任务的装备组合与美化对照

继续使用后台原有基准面板。在候选装备卡中展开“装备组合与美化”，选择“完整装备与组合”：单件填写一行，两件套或双美化填写两行，每行指定不同的非饰品部位。

例如，同一候选中的两件制造装备：

```text
wrists=,id=239660,ilevel=289,crafted_stats=crit/haste
back=,id=239661,ilevel=289,crafted_stats=crit/haste
```

每件必须有装备 ID 和装等。制造装备应填写实际副属性；宝石、附魔、美化奖励号等沿用 SimC 装备行格式。美化可以来自装备自身、`bonus_id` 或 `embellishment`。不要把同一个美化同时写成多个来源。快捷输入仍支持单件装备的多个装等；不同装等的完整组合分别添加候选。

## 职业专精适用检查

创建基准执行计划及普通配装、饰品比较任务时，按所选职业专精检查每件装备的职业限制、专精限制、护甲类型、武器类型、部位和主属性。不适用的候选不会进入任务的冻结候选列表，也不会生成对应 Run 或无特效对照；组合中任一成员不适用时整组跳过。

例如，火法排除板甲和力量饰品，狂怒排除仅支持敏捷 / 智力的装备。可随专精切换的主属性按其支持范围判断；无主属性的通用饰品、戒指和披风不会仅因没有力量而排除。护甲专精沿用配装器规则，只选择对应护甲类型。

判定资料由本地装备身份及当前活动目录变体批量读取，不在创建任务时临时联网。资料不足时先跳过，基准配置卡显示未参与的专精及原因；普通比较在创建提示中显示跳过列表，全部候选均不可用时不创建空比较任务。同步完整目录后重新生成计划即可重新判定。

当前公开收益与补跑使用筛选后的计划；旧历史执行记录保留。该检查针对待比较的候选，不改写用户原始配装。

## 收益含义

- 饰品保持原来的全能模板对照。
- 非饰品单件和组合先将目标之外的美化装备替换为同属性、无自身特效的副本，两组使用相同背景。
- 候选组保留目标装备及效果；对照组将全部目标装备也替换为同属性副本。独立宝石和附魔保留，护甲与武器数值也核验一致。
- 组合收益为整组有特效 DPS 减去整组无特效 DPS，包含单件特效、两件套及它们的联动，不代表单独的套装奖励数值。百分比以该组合自己的无特效 DPS 为分母。
- 候选最多两个美化，每件最多一个美化来源；不进行“三美化对比两美化”。美化背景统一清空，所以单美化是一个对零个、双美化是两个对零个。结果表示这一背景下的收益，不等同于玩家已有另一个美化时的替换收益。
- 移除装备导致非职业套装件数不足时，显式关闭对应奖励；剩余件数足够时保留。职业套装仍由原有显式配置控制。

所有成员作为一个候选展示和补跑。缺失或失败的对照不会退回公共基准计算；补跑成功后恢复展示。新规则进入冻结快照和计算身份，不把旧口径结果当作新结果复用。

## 执行与规则更新

服务端和独立 Agent 都需要更新共享的 `simc_equipment_control.py`。原版 SimC 无需修改，无数据库迁移。每个有此策略的模拟在正式战斗前执行两次原生保存初始化，生成并回读核验装备；失败则报告错误，不猜测属性。

服务端的 `simc_equipment_rules.json` 从仓库中的 SimC 数据和 `simc_embellishment_catalog.json` 生成；后者记录自带美化装备的来源和快照信息。冻结时还合并本地装备目录已标记的自带美化身份。规则随候选发送给 Agent，不要求 Agent 自行联网更新目录。

更新 SimC 数据或美化目录后，在项目目录运行：

```powershell
python scripts/build_simc_equipment_rules.py
```

检查生成差异后与服务端代码一起发布并重启工作进程。新版本装备需要对应目录身份和 SimC 支持；已知名称以外的显式美化会拒绝执行。该规则表不是对未来未知物品的自动识别器。

## 验证范围

本次以原版 SimC 1205-01、DBC 12.0.7.68974 完成普通两件套、制造两件套和双美化的六次真实战斗模拟，逐部位常驻属性在两组间一致。短模拟用于验证流程，不作为正式收益结论。部分制造效果在该引擎中有尚未完成游戏数值验证的提示，具体效果精度仍以对应 SimC 版本实现为限。
